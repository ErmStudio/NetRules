# Как устроено

## Поток трафика

```
        ┌──────────── LAN (192.168.1.0/24) ────────────┐
        │                                              │
   client :80/:443                                     │
        │                                              │
   mangle PREROUTING  MARK 0x40000000                  │
        │                                              │
   nat PREROUTING  REDIRECT :7892 ──► mihomo            │
                                        │              │
                        ┌───────────────┴───────────┐  │
                      PROXY                       DIRECT
                        │                           │
                    туннель              POSTROUTING nfqws2 (zapret)
                        │                           │
                        └────────► eth3 ◄───────────┘
```

- Помеченный трафик zapret не трогает (`mark 0x40000000` — «пропустить»).
- `DIRECT`-соединения mihomo уже немаркированные — их досылает zapret в POSTROUTING.
- QUIC (UDP 443) не проксируется: видео YouTube идёт через QUIC и обходит туннель.

## DNS

- DoH: Cloudflare и Google (HTTP/2 обязателен для части провайдеров).
- `filter engine` отключён, иначе статические `ip name-server` игнорируются.
- `ip name-server 192.168.22.2 logistik.ru` — корпоративная зона через L2TP.
- DHCP-опция 15 `domain logistik.ru` включает короткие имена.

## Компоненты панели

**api.cgi** — единственный бэкенд. Отдаёт JSON, читает состояние из:
- `iptables -t nat -S PREROUTING` — включены ли правила mihomo;
- файла правил — включены ли соцсети/видео;
- `ps` — запущен ли zapret;
- `netstat` — слушает ли mihomo;
- API mihomo `/proxies/*`, `/connections` — узел, задержка, трафик.

**speedtest.sh** — берёт топ-5 узлов по задержке из `/group/AUTO/delay`,
для каждого переключает группу `PROXY` (PUT `/proxies/PROXY`), качает 2 МБ через
локальный прокси-порт (`curl --proxy 127.0.0.1:7890 -w %{time_total}`), выбирает
самый быстрый и закрепляет его.

**checkall.sh** — получает список всех узлов через `/proxies`, проверяет их
параллельно (`xargs -P 16` + `check1.sh`), пишет статистику в `nodes_health.json`.

**watchdog.sh** — каждые 60 секунд:
1. проверяет, что порт 7892 слушает;
2. дёргает задержку группы AUTO;
3. если узел закреплён вручную — проверяет именно его и при двух сбоях
   возвращает `AUTO` и запускает новый замер;
4. после трёх сбоев перезапускает mihomo, после трёх перезапусков за час —
   снимает правила (fail-safe, чтобы не остаться без интернета).

**tasks.sh** — расписание:
- каждые 2 часа (по чётным) — замер скорости;
- 05:10 — бэкап;
- 05:00 по воскресеньям — `opkg upgrade mihomo`;
- 06:00 — обновление подписки.

**update.sh / update.py** — скачивают подписку sing-box, конвертируют в YAML
mihomo (vless/trojan, tcp/grpc/ws), перезапускают, при падении откатываются на
`config.yaml.bak`; после успеха пишут `last_update.txt` и запускают замер.

## Файлы состояния

| файл | что внутри |
|---|---|
| `last_update.txt` | `OK\|дата\|узлов` или `FAIL\|дата\|причина` |
| `countries.txt` | `узел\|страна` — из флагов в подписке |
| `nodes_health.json` | результат полной проверки узлов |
| `speedtest.json` | последний замер скорости |
| `.last_sub`, `.last_backup`, `.last_speed` | метки расписания |

## Безопасность

- Секрет API и адрес вынесены в `/opt/etc/mihomo/ui.conf` (в git не попадает).
- Панель слушает LAN на `:8090` без авторизации — не выставляйте её в интернет.
- `ui.conf` рекомендуется `chmod 600`.
